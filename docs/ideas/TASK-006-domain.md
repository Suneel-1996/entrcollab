# TASK-006 — Idea/project domain contract

## Scope

One Prisma model, IdeaProject, represents the initial idea/project aggregate. There is no separate Project/team/role/membership entity or implicit conversion. This task adds persistence and reusable pure policy definitions, not public APIs, discovery, AI processing or mobile UI. Backend authoring/read endpoints remain TASK-007 and are not authorized by this task.

## Fields and persistence

| Field | Representation/default |
| --- | --- |
| id | Internal UUID primary key, generated by Prisma. |
| ownerId | Required application user UUID; FK with ON DELETE RESTRICT. Multiple records per owner allowed; no ownership quota was approved. |
| title | Required VARCHAR(120), non-whitespace title CHECK. |
| summary | VARCHAR(280), default empty. |
| description | VARCHAR(5000), default empty. |
| neededSkills, tags | String arrays, default empty; nonnull, one-dimensional, no null entries, at most 20 entries each by SQL constraints. |
| status | DRAFT default, PUBLISHED or ARCHIVED. |
| visibility | PRIVATE default or MEMBERS. Separate from lifecycle; publication never implicitly shares. |
| createdAt, updatedAt | timestamptz(3), Prisma creation/update behavior. Direct SQL must supply updatedAt and id as needed. |
| publishedAt, archivedAt | Nullable timestamptz(3); lifecycle/date shape constrained by SQL. |

Field text is plain text, not executable HTML. API-layer trimming, unsupported control-character rules, per-entry length/deduplication, request-body validation and required publication content belong to TASK-007; no endpoint currently accepts user-supplied idea content. Do not treat a Prisma type or this schema as authorization. No email, provider credential, contact information, embeddings or model output is added.

## Lifecycle

| Current | Next | Time effects |
| --- | --- | --- |
| DRAFT | PUBLISHED | Set publishedAt to server-supplied operation time; archivedAt remains null. |
| DRAFT | ARCHIVED | Set archivedAt; publishedAt remains null. |
| PUBLISHED | ARCHIVED | Preserve publishedAt, set archivedAt. |
| ARCHIVED | Any | Denied, including same-state/restore/unpublish. |
| Any | Same state | Not a lifecycle edge; denied. |

Only a verified active/non-held owner may transition. Timestamps must be finite and no earlier than creation or prior publication. `ideaTransitionFields` returns new lifecycle fields without mutating the original record or visibility. It expects persisted records and a trusted server operation time. SQL CHECKs require draft timestamps both null, publication timestamp present without archive timestamp, and archive timestamp present; publication/archive cannot precede creation or each other.

CHECK constraints validate a row, not its history: direct privileged SQL can bypass transition/actor policy while producing a valid row. No trigger or public update service was added. TASK-007 must call the policy with verified caller/database owner state and perform lifecycle updates atomically against the expected current state. There is no completed HTTP authorization, idempotency or concurrency service to claim here.

## Read matrix

Caller and target owner must both be ACTIVE with deletionRequestedAt null. Otherwise deny. With those checks:

| Record | Owner | Other active signed-in user | Anonymous |
| --- | --- | --- | --- |
| DRAFT, any visibility | Read | Deny | Deny |
| PUBLISHED/PRIVATE | Read | Deny | Deny |
| PUBLISHED/MEMBERS | Read | Read | Deny |
| ARCHIVED, any visibility | Read | Deny | Deny |

This is whole-record visibility, separate from profile field visibility. No public/unlisted access or implicit team/connection relationship is granted. `canReadIdeaProject`/`canTransitionIdeaProject` use trusted application IDs/account state, never client role/status claims. Future member responses must not serialize owner account objects, provider subjects or account-status/deletion metadata. Future APIs must avoid exposing inaccessible-record existence and raw DB errors; those HTTP contracts are not implemented by this task.

## Index and migration review

- `IdeaProject_owner_state_updated_idx`: ownerId, status, updatedAt DESC, id DESC. Supports future owner/state keyset reads.
- `IdeaProject_state_visibility_updated_idx`: status, visibility, updatedAt DESC, id DESC. Supports future visibility-filtered reads; an index is not a discovery endpoint or permission control.
- No GIN/full-text/vector index, search pipeline, counter, AI metadata or role table is introduced.

Migration `202610150002_idea_project` creates only enums, table, indexes, FK and CHECK constraints. Existing identity/profile tables and rows are not rewritten/dropped. Old applied migration checksums are preserved. SQL constraints are intentionally hand-reviewed additions beyond Prisma's generated DDL; Prisma schema diff does not describe/validate all CHECK semantics. Preserve them in future migrations and use database negative tests to verify them. The migration is reviewed for implementation correctness; this does not assert final owner acceptance.

Apply the existing `npm run db:generate`, `npm run db:validate`, `npm run db:deploy` workflow. Repeated deploy is idempotent. No new config variables, service subscriptions or network destinations are required. Tests clean up randomized fixtures only; this is not a product deletion feature.
