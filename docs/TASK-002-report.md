## Implementation

- Mobile: Supabase PKCE Google OAuth through Expo system browser, exact configured callback correlation, S256 enforcement, one active/expiring attempt, captured SDK verifier flow ID, generic loading/cancellation/error states. Platform SecureStore chunk adapter supports long sessions without plaintext fallback. Session restore, refresh, foreground revalidation, expiry and local sign-out are implemented. Development email OTP is off by default; server OTP/allowlist checks remain authoritative.
- NestJS: `GET /api/v1/auth/me` validates trusted issuer/JWKS signature, audience, expiry, required claims, subject and provider policy. No client-supplied IDs/roles/status are trusted. Generic 401/403/503 and no-store responses avoid sensitive details. Application state is checked on each request. Existing health/readiness behavior is preserved.
- PostgreSQL/Prisma: additive reviewed identity migration, internal UUID, unique provider subject, ACTIVE/SUSPENDED status, timestamps and optional deletion hold. Concurrent provisioning reuses one identity and never resets account restrictions. No provider credentials are stored.
- Linking, permanent deletion and recovery policy decisions remain deferred. No account administration/deletion endpoint was invented. Multi-provider sessions fail closed.
- Setup, lifecycle, quotas and security boundary: [authentication](auth/TASK-002-authentication.md), [account lifecycle](auth/TASK-002-account-lifecycle.md), [cost controls](auth/TASK-002-cost-controls.md), [ADR-002](architecture/ADR-002-supabase-development-auth.md).
